Qwen3-VL-4B-Instruct · MMMU 정확도 높이기 · 2026-11-22 기준

**읽는 법**
- 정확도는 따로 적지 않으면 MMMU val 900문항, Pipeline 채점(답 줄 → fallback → 공식 파서), 단위 %다.
- 평가 환경이 다른 숫자끼리는 비교할 수 없다. 그래서 각 실험 옆에 **같은 환경에서 잰 Baseline**을 함께 적었다.

- 문항별 결과 파일은 [`MMD/results/`](../MMD/results)에 있다. 사용법과 재현 방법은 [README](../README.md)에 있다.

## 0. 평가 설정 만들기 (학습 없음, 9월)

**목적:** 모델을 학습하기 전에 Baseline을 공정하고 안정적으로 잴 방법부터 정한다.

| 설정 | 내용 | 정확도 |
|---|---|---|
| 기본 preset | MMMU 공식 프롬프트("answer directly"), 출력 상한 8,192, seed 42 | 59.56 |
| 프롬프트 A/B (90문항) | 공식 / Qwen CoT / 강제 CoT | 56.7 / 63.3 / 62.2 |
| **best preset** | Qwen CoT 프롬프트, 출력 상한 32,768, 고해상도, seed 3407, 잘림 시 fallback | **65.22** (팀 Baseline) |
| best, seed 1234 | seed만 변경 | 65.89 |
| **best_r2u** | best + 작은 이미지 업스케일 | **65.56** (최종 Baseline) |
| best_r2u, seed 1001 / 1002 | seed만 변경 | 64.22 / 65.78 |
| 3회 다수결 | 세 seed 결과로 투표 | 66.44 (p=0.33) |
| 잘림 재풀이 1회 / 2회 | 잘린 답만 다른 seed로 다시 풀기 | 66.67 (p=0.041) / 66.78 |
| repetition_penalty 1.05 | 반복 억제 | 60문항에서 중단, 점수 없음 |

**알게 된 것**
- 프롬프트와 출력 상한만 바꿔도 +5.7%p가 올랐다.
- 남은 오류의 큰 원인은 **답을 끝내지 못하고 출력 상한에 걸리는 잘림**(88건)과 **반복 루프**(62건)였다.
- 잘린 답만 다시 풀어도 +1.1%p가 올랐다. 그래서 잘림을 줄이는 것을 학습 목표로 삼았다.

## 1. STIC 파일럿 (10월, 공학 도식 80문항)

**목적:** 이미지 설명을 학습에 넣으면(STIC 방식) 공학 도식 문제가 나아지는지 작게 확인한다.
**설정:** 기계·재료·전자·건축 각 20문항(학습 48 / 검증 16). 채점은 rubric 기준이다.

| 실험 | 검증 16문항 |
|---|---|
| Base | 9/16 |
| 일반 LoRA (attention, r8) | 9/16 |
| 설명 조건부 LoRA | 10/16 (설명 입력 시 9/16), p=1 |
| 구조 문제 진단: 이미지 → 모델 | 0/4 |
| 구조 문제 진단: 모델이 뽑은 조건 → 계산기 | 2/4 |
| 확대, 단계별 추출, 규칙 후처리 | 모두 0/2 |

**알게 된 것:** 학습으로는 달라지지 않았다. 계산 단계가 아니라 **도식을 읽고 조건을 뽑는 단계**가 막혀 있었다.

## 2. Phase 1: 시각 연결부와 입력 해상도 (11월 초)

**목적:** ViT는 고정한 채, 시각 정보를 LLM에 넘기는 부분(connector)이나 입력을 바꿔 도식 해석을 개선한다.
**평가:** MechVQA test 100문항, Qwen2.5-7B 채점 모델(v2 기준). 100문항이라 표준오차는 약 5점이다.

| 실험 | 학습한 것 | MechVQA |
|---|---|---|
| A: Base | 없음 | 47 |
| B1 | 메인 merger | 52 |
| B2 | merger + DeepStack merger 3개 (lr 1e-5 / 1e-4 / 5e-4) | 55 / 55 / 49 |
| R1 → R2U | 학습 없음, 입력 해상도만 키움(업스케일) | 50 → **59** |
| D | R2U + 공간 어댑터 | 60 |
| IAA | 정답 문장으로 LLM LoRA | 60 (같은 서버 Base 60) |
| **자기 증류 E: ELLM** | Base의 8개 CoT 샘플 중 정답 풀이(2,083행)로 LLM LoRA | 학습만 완료(val loss 0.117), **평가 안 함** |
| **자기 증류 E: E-Both** | 같은 데이터로 connector + LoRA | 학습 완료 기록 없음, 평가 안 함 |

**진단 실험 (학습 없음)**
- 어려운 16문항을 해상도·타일을 바꿔 다시 풀림: 0–3개만 맞음.
- ChartQA 70문항: 54 → 55.
- 8번 모두 틀린 34문항 중 10개를 이미지 없이 글로만 물음: 4/10 정답.

**알게 된 것**
- connector 학습은 입력 업스케일(학습 없음)을 넘지 못했다.
- 오류의 상당수는 이미지가 아니라 **LLM의 지식과 추론** 쪽에 있었다. 그래서 다음 단계부터는 LLM LoRA로 방향을 바꿨다.
- Phase 1 모델은 MMMU로 평가하지 않았다.

- **모델이 스스로 만든 정답 풀이**로 학습하면 점수가 유지되고 잘림이 줄었다. 이것이 최종 설계(H 계열)의 근거가 됐다.

## 4. Phase 2: H 계열 (최종 설계, 11월 중순)

**공통 설정:** ViT 고정, LLM attention q·k·v·o에 LoRA(r16, α32), seed 3407.
**데이터:** Base에게 ViRL 문항을 한 문항당 6–8번 풀게 했다. 그중 정답률이 너무 낮거나 높지 않은 문항에서 정답 풀이(SFT 637개, build2)와 정답·오답 쌍(DPO 672쌍)을 뽑았다. 1차 생성(build)은 3,267문항에서 샘플 정답률 86.2%였다.
**평가:** 최종 설정 best_r2u. Baseline은 65.56이다.

| 모델 | 학습 | 정확도 | Strict | 잘림 | 루프 |
|---|---|---|---|---|---|
| Baseline | – | 65.56 | 62.78 | 88 | 62 |
| **H-SFT** | 자기생성 정답 풀이 SFT, 80 step | **66.89** | 63.33 | **45** | 23 |
| H-SFT (1회차) | 같음 | 66.22 | 63.00 | 47 | 21 |
| **H-SFT + 재풀이** | 잘린 답만 다시 풀기 | **67.00** | 64.44 | 14 | 5 |
| Baseline + 재풀이 | 같은 방법 | 66.67 | – | – | – |
| H-DPO | 정답·오답 쌍 DPO (β 0.1), 84 step | 65.33 | 62.11 | 107 | 85 |
| H-DPO 변형 | 더 큰 쌍 데이터(1,116쌍) DPO | 64.56 | 62.33 | 104 | 89 |
| Baseline, 이미지 없이 | – | 46.22 | – | – | – |
| H-SFT, 이미지 없이 | – | 48.89 | – | – | – |

**교사 증류 (Qwen3-VL-32B → 4B)**
- **목적:** 더 큰 모델(32B)의 풀이로 4B를 가르치면 나아지는지 본다.
- **데이터:** 교사는 300문항 시험에서 77.0%를 맞혔다(4B는 63.0%). 교사가 맞힌 풀이 2,153개로 학습했다.

| 모델 | 학습 | 정확도 (상한 32,768) | 정확도 (상한 2,048, 서버) |
|---|---|---|---|
| Baseline | – | 65.56 | 61.78 |
| T-SFT | 교사 풀이 SFT, attention LoRA r64, 539 step | **62.78** | 62.67 |
| TM-SFT | 같은 데이터, attention + MLP LoRA | – | 62.33 |
| H-DPO / H-DPO 변형 | – | 65.33 / 64.56 | 61.2 / 60.9 |

- **합성 문항 (실험 S):** 교사가 이미지로 새 문제를 만들게 했다(100개 중 80개 사용 가능, 학습용 54행). 학습과 평가는 하지 않았다.

**진단 (Baseline 대 H-SFT, 문항별 비교)**
- 정답이 바뀐 문항은 65 대 71이다(p=0.67). **정확도 차이는 유의하지 않다.**
- 잘림은 60 대 19로 바뀌었다(p<0.0001). **잘림 감소는 확실하다.**
- 둘 다 끝까지 푼 793문항에서는 68.7 대 68.9로 같다. 즉 H-SFT는 "더 똑똑해진 것"이 아니라 "끝까지 푸는 것"이 나아졌다.
- 교사 증류(T-SFT)는 끝까지 푼 문항에서 Base만 맞힌 문항이 81, T-SFT만 맞힌 문항이 51이었다(p=0.011). 실제로 손해였다.

**알게 된 것**
- 모델 자신의 정답 풀이로 SFT한 H-SFT만 Baseline 수준을 지키면서 잘림을 절반으로 줄였다.
- DPO와 교사 증류는 오히려 나빠졌다.
- Baseline도 재풀이를 하면 66.67이 나온다. 그래서 H-SFT의 이득은 "재풀이 없이 한 번에 비슷한 결과를 낸다"는 데 있다.

## 결론

1. **가장 큰 이득은 학습이 아니라 평가 설정에서 나왔다:** 59.56 → 65.22, +5.7%p.
2. **연결부와 외부 데이터 학습은 효과가 없거나 해로웠다:** connector, 분야별 LoRA, 교사 증류, DPO 모두 그랬다.
3. **자기생성 정답 풀이로 attention LoRA만 학습한 H-SFT만** 정확도를 지키면서 잘림을 88 → 45건으로 줄였다 (1회차 47건). MMMU-Pro에서는 +1.06%p였다.
4. **남은 한계:** MMMU val에서의 정확도 차이는 통계적으로 유의하지 않다. 공학(Tech & Engineering)이 가장 약하다(test 56.32).
5. **평가하지 못한 실험:** 자기 증류 ELLM·E-Both, IAA, Phase 1 모델들의 MMMU 결과, pass@8 요약은 남아 있지 않다. 일부 원본은 연구실 서버에만 있다.
